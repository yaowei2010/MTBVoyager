# fastVEP GRCh38 correction record — 2026-10-16

## Corrected

1. The CLI wrapper now mounts the official MTB reference directory read-only
   at `/mtb-reference`.
2. Added `run-hg38.sh`, which pins:
   - Ensembl 112 GFF3;
   - official MTB `hg38.fa`;
   - `grch38_ensembl112.mtb.cache`;
   - the current fastVEP supplementary annotation directory.
3. The web/Compose service now uses the same FASTA and transcript cache.
4. Added `verify-hg38.sh` to reject missing or checksum-mismatched GRCh38
   resources before testing.
5. Updated the reference manifest with runtime mount paths, fastVEP version,
   commit and AlphaMissense checksum.
6. Documented that the historical local `data/reference/hg38.fa` symlink has a
   different checksum and must not be used for the MTB comparison profile.
7. Added canonical chromosome filtering for every VCF input.
8. Built a canonical-only Ensembl 112 GFF3 and transcript cache containing
   chr1–chr22, chrX, chrY and chrM/MT only.

## Verification result

The Ensembl VEP example containing 173 variants was rerun with the pinned MTB
GRCh38 profile:

| Metric | Result |
|---|---:|
| Input variants | 173 |
| Transcript consequences | 1,580 |
| Generic `coding_sequence_variant` degradation | 0 |
| `missense_variant` consequences | 366 |
| `synonymous_variant` consequences | 506 |
| Consequences with HGVSp | 872 |
| Non-canonical chromosomes in output | 0 |
| Alternate-contig missing-sequence warnings | 0 |

This confirms that supplying both the cache and official FASTA preserves
sequence-aware coding annotation.

Non-standard contigs are intentionally outside this profile and no longer
appear in input processing, cache loading or output.

A two-record control VCF containing one `chr1` record and one
`chr1_KI270706v1_random` record produced exactly one output variant on `chr1`;
the random-contig record was removed before annotation.
